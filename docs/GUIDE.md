# GaplessPlayer 使用说明（GUIDE）

> 这份文件是「怎么用、怎么调、出问题怎么查」。
> 和上游原作者的差别、以及各版本新增/修复了什么，看 [README](../README.md)。

## 1. 支持范围

| 客户端 | 支持 | 预载音质 |
|---|---|---|
| 2.10.x | ✅（上游原样） | 320k |
| **3.1.x** | ✅ 本分支（实测 `3.1.42.205594`，需 BetterNCM 1.3.4） | 320k（拿不到退 128k） |

## 2. 安装

1. 到 **Releases** 下载最新的 `gapless-player-*.plugin`（同一个 Release 里附带可选依赖
   **`LibEAPIRequest.plugin`**，建议一起下）；
2. 两个 `.plugin` 都放进 `C:\betterncm\plugins\`；
3. 重启网易云。

装好之后不用点播放、不用改快捷方式：插件会自己接管。
**播放器栏「随机播放」左边有一颗 ♪** —— 点它打开设置面板。

> 这颗 ♪ 是**浮层**（`position: fixed`，位置按随机播放按钮实时算），**不在客户端的组件树里**，
> 所以点它不会连带触发随机播放。找不到播放器栏时会退回右下角浮标。
> `window.__gpHideButton = true` 可隐藏。

关于 `LibEAPIRequest`：它是取址/预载用的依赖。**不装也能播**，但 2.10.x 上会取不到地址 →
退化成纯流式（没有预载、也就没有采样级接缝）；3.1.x 有免签名接口兜底，不装也能预载。

想要**桌面歌词**的话建议一并装 [RuLyric](https://github.com/BetterNCM/RuLyric)：
网易云自带的桌面歌词由原生渲染，插件按住原生播放器后它只剩歌名。

## 4. 交叉淡入淡出（v1.3.0 起，v1.9.4 一个开关，v1.14.0 变智能）

- 默认**关** → 干净无缝（B 从 A 的最后一个采样之后开始，不淡不叠）；
- 打开 → **智能交叉**：时长按 A 的 BPM 取整小节、曲线按档位自动选（见下）；
- 显式设置永远优先：`setXfade(6)`、`__gpXfadeCurve`、面板「时长 ±」都会退出智能；
- 高通扫频仍默认关；**低置信 / 节奏差时自动跳过交叉**（v1.17.0，见下）。

| 档位 | 时长 | 曲线 |
|---|---|---|
| `full`（两边置信 ≥0.45、偏差 ≤6%） | 2 小节 = 8 拍（夹 2~10s） | `r_s-line`（端部更陡） |
| `smart`（置信 ≥0.2） | 1 小节 = 4 拍（夹 2~10s） | `s-line`（平滑 S） |
| `plain`（对不上/没拍点） | 你设的秒数（默认 3s） | `equal`（等功率，最中性） |

**跳过交叉**（v1.17.0）：两个节奏明显打架、或者根本测不准时，3 秒交叉不如切。

| 情况 | 判定 | 行为 |
|---|---|---|
| 任一侧没有网格 | `no-grid` | 跳过 |
| `min(conf) < 0.1` | `low-conf` | 跳过 |
| 偏差 >6%（v1.20.0 起不看置信） | `tempo-far` | 跳过 |
| 其余（偏差 ≤6%、conf ≥0.1） | — | 普通交叉，不跳过 |

「跳过」= 不排交叉，B 在「A 结束 − 20ms」起、两边 20ms 等功率淡出/淡入；
不做 A 提前收尾；B 入点只跳过开头静音。`拍点对齐` 关掉时不跳过。
状态行/大卡会写 `跳过 · 节奏差` / `跳过 · 置信低` / `跳过 · 没有拍点`；
逃生开关：`window.__gpSkipBadMix = false`。

**连续母带**（v1.19.0，无缝专辑）：概念专辑 / 古典 / 现场 / DJ mix 的 A 尾音直接切进
B 开头（没淡出、没静音、电平也接得上）。满足下面四条就**保持原样**（0s 接缝），
不交叉、不早收、不跳 B 的入点：

1. A 结尾 0.25s 有声音且不低于全曲平均的 35%（没淡出）；
2. B 开头 0.25s 有声音且不低于全曲平均的 35%（没淡入）；
3. A 没有尾部静音、B 没有头部静音（`trim` ≤ 20ms）；
4. 两侧边界电平差 ≤ 6dB。

面板大卡会写「原样」，日志 `[automix] 连续母带 → 保持原样`。
关闭：`window.__gpKeepContinuous = false`。
A 走流式（没有 AudioBuffer）时测不了尾音，这条不生效。

**同专辑相邻**（v1.20.0 兜底）：歌单条目里带了 `album` / `artist`，所以再加一层——
**同一张专辑 + 在列表里相邻 + B 开头没有静音（`trim.start ≤ 20ms`）→ 直接 0s 原样**，
不依赖 A 的缓冲（流式 A 也能判）。普通专辑曲间有留白时不会命中。
日志：`[automix] 同专辑相邻（专辑名）→ 保持原样（0s 接缝，元数据兜底）`。

**拍点对齐**（有交叉时才有意义）：插件自己算两首歌的 BPM 与拍点（分析已解码的缓冲，
不额外下载），然后：

1. **A 的尾窗取两窗**（v1.18.0）：最后 22 秒 + 「结尾前 10 秒起 20 秒」；一致（±2%）就融合抬置信，
   不一致取置信高的 — 提前收尾后混音点往前挪，也不会对着淡出段量拍；
   **B 的头窗也取两窗**（v1.20.0）：开头 20 秒 + 「第 8 秒起 20 秒」，长前奏/氛围前奏不再把 BPM 带偏；
2. **交叉起点**吸到 A 的最近一拍（偏移 ≤ 半拍）；
3. **交叉时长**：智能模式取小节（上面那张表）；显式模式才折整拍
   （128 BPM 下 3s → 2.81s = 6 拍，偏差 >15% 就保留你设的值）；plain 回退**不再折拍**，
   直接用你设的秒数（v1.18.0）；
4. 给 **B 选入点**：跳过开头空白/留白，落在第一拍/乐句头（最多跳 6 秒，超了就老实从 0 开始）；
   **干净风格（0s 交叉）也会跳过开头空白**，只是不做拍点对齐 —— 免得接缝处留个 1~2 秒的洞；
5. **A 提前收尾**（v1.9.2）：在 outro 掉点 / 乐句头处就把 A 收掉（最多 8 秒），
   淡出边界落在音乐点上，而不是「歌放完了才开始淡」。`window.__gpEarlyOut = false` 可关。

**BPM 判定**（v1.9.2 重做）：置信度用「拍上 vs 拍外 / 拍上 vs 整段平均」双对比度 + 相位显著性 +
覆盖率 + 瞬态锐度；头尾两个窗口**测出同一个速度会互证加分**，成 2/3 倍关系（如 `尾 85 vs 头 160`）
判为「同一速度的不同拍级」而不是测错。

两首 BPM 八度折算后偏差 >6% 就不硬对齐。**整首不变速**（交叉那一段有 WSOLA 保音高贴拍，±6% 内）。

**为什么有时候听起来还是固定 3 秒？** 上面这些都需要「A 的尾窗网格」和「B 的头窗网格」。
B 通常被预载成缓冲，没问题；A 如果走 `<audio>` 流式，本来**没有 AudioBuffer**，
v1.9.7 以前就直接退成普通 3s 交叉。v1.10.0 起拍点/能量会落盘（`analysis.json`），
**流式 A 也能拿到上次算好的网格** → 吸拍 / 量化 / 贴拍照常生效。
日志里能看得很清楚：`[automix] A=120.0bpm/置信1.00 → full` 而不是 `A=无 → plain`。

**v1.17.0 起，这种情况会直接「跳过交叉」**：`A=无` / 置信 <0.1 / 节奏差 → 20ms 极短淡，
不再用 3 秒把两个不相干的节奏糊在一起。想强制保留 3s：`window.__gpSkipBadMix = false`。

**补算与融合**（v1.11.0 / v1.12.0）：盘上有字节却没有分析记录的歌，会在空闲时补算；
补算用**头/中/尾三个窗**，八度折算后取中位数、按一致比例加权置信。
某一窗测歪（自由节奏前奏、加花尾段）会被另外两窗拉回来 —— 锚点不投票，
而是从「相位可信且离目标最近」的那一窗外推。融合失败的歌记为 `w=1` 且不再重试。

## 5. 响度平衡（v1.9.0 起，v1.9.3 重做）

接缝再准，「一声大一声小」照样毁听感。插件会按曲目归一化音量：

- 数据来源三条腿（缺一个退下一个）：`player/url` 的 **`gain`/`peak`** →
  `song/detail` 的 **`volumeDelta`**（量纲 1e-4 dB，和客户端「音量平衡」同源）→
  **直接从解码缓冲量 RMS**（不依赖任何接口）。三者参考电平不同，会先按来源对齐再统一算；
- 施加的是**相对本库中位数**的差值，不是接口原始值：

  ```
  施加 = 已测增益 − 中位数(所有已测曲目)
  ```

  效果是「歌与歌被拉到同一响度」，但**整体音量不变**（中位数那一首正好 0 dB）；
- 每路一个固定增益节点：`源 → 交叉曲线 → 高通 → 响度归一化 → 音量条 → 输出`；
- **峰值保护**：要提音量时先算「到 -1 dBFS 还剩多少余量」，不够就不提；拿不到峰值就不提；
- 上限：最多压 12 dB、最多提 6 dB（`__gpLoudCut` / `__gpLoudBoost`）；
- 数据「播到一半才补上」时，会在 0.25s 内平滑过渡（不咔哒）；
- `__gpLoudRef = "none"` 退回绝对模式（直接施加接口原始增益）；`__gpLoudness = false` 全关。

日志里每首会有一行 `[loud] 归一化 track=… ｜ -5.0 dB ｜ 缓冲 ｜ 原始 -8.4 / 参考 -3.4 ｜ 峰值 0.98`。

## 6. 缓存分三层（v1.8.4 起的磁盘层）

| 层 | 内容 | 上限 | 清掉之后 |
|---|---|---|---|
| 解码缓冲 | `AudioBuffer`（现成能播） | 2 首 / ≤160MB | 要重新解码 |
| 内存字节 | 压缩字节（免下载） | 2 首 | 要重新下载 |
| **磁盘字节** | 压缩字节落盘 | 默认 300MB | 要重新下载 |
| **离线分析** | 拍点网格 + 每秒能量（`analysis.json`，一首约 400 字节） | 2000 首 | 下次分析时再算 |

- 目录 `C:\betterncm\gapless-cache`（`__gpDiskDir` 可改）；
- 清内存**不动磁盘**，清完立刻重排预热；清磁盘之后下一次预载要重新下载；
- **离线分析**和音频缓存解耦：音频被淘汰了它还在。有了它，**流式 A（没有解码缓冲）
  也能拿到 BPM 网格** → 交叉起点吸拍 / 时长量化 / 变速贴拍才能生效；
  算法升级会按版本号整批作废，曲目时长对不上（试听片段/换音质）时单条作废重算；
- **补算**（v1.11.0）：盘上有字节、却没有分析记录的歌，会在空闲时一首首
  「读盘 → 解码 → 分析 → 丢弃缓冲」。开机 15s 后起步、串行、每首间隔 2s、每会话 ≤30 首；
  不下载、不占解码缓冲、不刷新磁盘 LRU。坏字节记进 `skip`（连续失败 2 次 → 7 天不再试）。
- `__gpDiskCache = false` 关掉整层；`__gpDiskMB = 300` 改上限；`__gpAnalysis = false` 只关离线分析；
- 开机有一行自检（写→读→删），写不进去会说明原因（不再是「磁盘=0 首」的无头案）。

## 7. 开关（控制台一行，立刻生效）

| 开关 | 作用 | 默认 |
|---|---|---|
| `window.__gpXfade = 3` | 交叉时长（0~12s，会记住）；显式设置会**关掉智能** | 0（干净） |
| `window.__gpXfadeSmart = false` | 只关「智能时长/曲线」，仍按秒数走 | 随面板开关 |
| `window.__gpSkipBadMix = false` | 关掉「低置信/节奏差跳过交叉」 | 开 |
| `window.__gpKeepContinuous = false` | 关掉「连续母带保持原样」 | 开 |
| `window.__gpXfadeCurve` / `__gpXfadeEq` | 交叉曲线 / 高通扫频 | equal / 关 |
| `window.__gpEarlyOut = false` | 关掉 A 提前收尾 | 开 |
| `window.__gpAutoMix = false` | 关掉拍点对齐（不分析、不对齐） | 开 |
| `window.__gpLoudness = false` | 关掉响度平衡 | 开 |
| `window.__gpLoudRef = "none"` | 响度用绝对模式 | 相对（中位数） |
| `window.__gpLoudCut` / `__gpLoudBoost` | 响度最多压/提多少 dB | 12 / 6 |
| `window.__gpTrim = false` | 完全关掉首尾裁剪 | 开 |
| `window.__gpTrimPad = true` | 连「作品静音」也裁（默认只裁编码器填充） | 关 |
| `window.__gpPromote = false` | 不把流式那首补成缓冲（省流量） | 开 |
| `window.__gpCache` / `__gpBytesCache = false` | 关全部缓存 / 只关字节缓存 | 开 |
| `window.__gpDiskCache = false` / `__gpDiskMB` / `__gpDiskDir` | 磁盘层开关 / 上限 / 目录 | 开 / 300 / 默认 |
| `window.__gpAnalysis = false` | 关掉拍点/能量离线缓存（跟着磁盘层一起关） | 开 |
| `window.__gpBackfill = false` | 关掉空闲补算 | 开 |
| `window.__gpBackfillDelay` / `__gpBackfillGap` / `__gpBackfillMax` | 起步延迟 ms / 每首间隔 ms / 每会话上限 | 15000 / 2000 / 30 |
| `window.__gpSeamless = false` | 关掉采样级预约（退回等 UI） | 开 |
| `window.__gpStream = false` | 强制走缓冲路径（排查跨域静音） | 开 |
| `window.__gpNativeAll = true` | 整条交回原生播放器（面板「插件启用」关掉就是这个） | 关 |
| `window.__gpHideButton = true` | 隐藏播放器栏那颗 ♪ | 关 |

脚本接口（面板用的就是这些）：

```js
gaplessPlayer.status()            // 一行状态
gaplessPlayer.xfade()             // {sec, curve, eq, source}
gaplessPlayer.xfadeOn()           // 交叉是否开着
gaplessPlayer.setXfade(true, 3)   // 开 3s；setXfade(false) 关；setXfade(6) 直接 6s
gaplessPlayer.setStyle("clean")   // 老调用：clean = 关，其它 = 开
gaplessPlayer.clearCache()        // 清内存
gaplessPlayer.clearDiskCache()    // 清磁盘
gaplessPlayer.diskStats()         // 磁盘层状态
gaplessPlayer.analysisStats()     // 离线分析层状态（首数/待补/跳过/路径/读写次数）
gaplessPlayer.analysisOf(id)      // 某首落盘的拍点/能量记录
gaplessPlayer.backfill()          // 手动催一次补算（返回 Promise<boolean>）
gaplessPlayer.audit()            // 置信度体检：读现有记录（conf 分桶/八度比/跳过原因）
gaplessPlayer.audit(true)        // 对盘上字节重算头/中/尾三窗（≤30 首、串行）
gaplessPlayer.rewarm()            // 手动重排预热
gaplessPlayer.predict()           // 为什么这首没预约（hitStreak / misses / nextOff…）
gaplessPlayer.beat(ab, from, len) // 拍点分析（诊断）
gaplessPlayer.beatGrid(id)        // 已缓存的头/尾网格
gaplessPlayer.loudness()          // 响度平衡总览（模式 / 参考 / 数据来源计数）
gaplessPlayer.loudnessOf(id)      // 单曲响度详情
gaplessPlayer.noteLoudness(id, {gain, peak})  // 手工喂一个测量值（调参用）
gaplessPlayer.quantizeXfade(sec, grid)        // 交叉时长量化到整拍（纯函数）
gaplessPlayer.reconcileGrids(head, tail)      // 头尾 BPM 收敛（纯函数）
gaplessPlayer.openPanel()         // 开/关面板
```

## 8. 日志与排错

日志：`C:\betterncm\gapless-player.log`（面板「更多 → 复制日志路径」）。

排错时先看这几行：

## 9. 已知限制

- **整首不做 tempo 对齐**：只对齐「交叉起点 / 时长 / B 入点」，交叉那一段内有 WSOLA ±6% 贴拍。
- **B 没缓冲完就一定没有无缝**：采样级接缝只认完整的解码缓冲（Web Audio 没有流式 buffer 源）。
  没预载时会预开流把空档从约 500ms 压短，但**不等于无缝**。
- **随机播放无法稳定无缝**：客户端切歌前约 80ms 才决定下一首，插件只能「押」
  （间隙已从约 0.5s 压到约 0.2s）。要 0 间隙请用**顺序播放 / 列表循环**。
- **A 提前收尾是行为变更**：开了之后歌不再必然播完（最多少播 8 秒）。不喜欢就 `__gpEarlyOut = false`。
- **BPM 检测仍不是万能的**：母带压得极狠、铺底比鼓点还响的曲子可能测歪；测不准时老实退回普通交叉。
- **响度平衡有上限**：压 12 / 提 6 dB；极少见的极端母带只会被「部分」拉平。
- **不装 `LibEAPIRequest.plugin`**：2.10.x 取不到地址 → 没有预载、没有采样级接缝（仍能播）。
- **流式那一首不做首尾裁剪**（`<audio>` 没有采样级定位）。
- **内存 / 流量**：最近缓冲最多 2 首（≤160MB）；流式曲目听够 8s 会补一份（~6MB/首）。
- **本次启动的第一首是原生播的**：那首没有无缝/交叉，点击任意位置后接管（autoplay 策略所限）。
- 付费/VIP 曲目若无权限，接口只给试听片段 → 这类曲目没有无缝（仍能完整播放）。
- 插件依赖客户端内部接口（`channel.call` / `legacyNativeCmder`），**客户端升级可能失效**。
