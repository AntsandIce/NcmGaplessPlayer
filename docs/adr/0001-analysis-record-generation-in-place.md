# 分析记录用「代数」原地升级，不作废整批

分析记录里的 `w`（这条记录用上了几个窗口）与 `tried`（补算时试过的那一代）让「算法换代」
变成可增量重算的升级：旧记录仍可读、仍能用来对齐，补算扫到它时再抬到新代数。
`ANALYSIS_V` 不跟着改 —— 它只留给真正的**格式**变化。

## 背景

v1.10.0 引入 `analysis.json` 时用 `ANALYSIS_V` 标识版本，不符就整批丢掉重算。这很适合「格式改了」，
但 v1.12.0 要做的是**算法**升级（单窗 → 三窗融合）。如果沿用版本作废，升级后到补算跑完之前，
所有歌都会失去网格，交叉退回固定 3 秒 —— 正好是这次要修的病。

## 考虑过的方案

- **抬 `ANALYSIS_V` 整批作废**：实现最简单，但升级瞬间「所有歌都没有拍点」。
- **双写两套记录**：读旧写新、迁完再删；读取与存储都要多一分支。
- **代数原地升级（选了这个）**：`w`/`tried` 记录「这一代做没做过」，`ANALYSIS_V` 只管格式。

## 后果

- 升级后旧记录立刻仍可用；补算把 `w` 从 1 抬到 3。
- 「什么算需要分析」收敛成单一判据 `analysisNeedsBackfill(rec)`，P2 与 P3 都不需要迁移脚本。
- 融合失败必须记 `tried=3`，否则会被当成「没试过」而每次开机重试。
- ⚠️ 以后看到算法改了、`ANALYSIS_V` 却没动，**不要以为是忘了 bump**：代数在 `w` 里。
