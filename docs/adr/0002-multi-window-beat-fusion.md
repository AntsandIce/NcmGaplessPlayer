# 补算用三窗融合：BPM 取中位数，相位从可信窗外推

交叉对齐要两样东西：**速度**（BPM）与**相位**（锚点/末拍）。补算对头/中/尾三窗各算一次，
速度取八度折算后的中位数、按一致比例加权置信；相位不投票 —— 只采用「本窗 BPM 与融合值同拍级」
的窗口，从中挑离目标最近的一个，用融合 BPM 外推到 0s / 结尾。

## 背景

单窗分析有两个无法自证的失败：某一窗落在自由节奏前奏 / breakdown 上，或落到加花段测成 2/3、4/3 倍速
（真机日志：`114.5 vs 142.1`、`99.6 vs 153`）。在播分析**不能**加窗 —— 起播路径多 20ms 就会让切歌慢半拍，
所以融合只在空闲的补算里做。

## 考虑过的方案

- **单窗 + 提高置信阈值**：治不了「测歪但很自信」。
- **五窗**：边际收益小，多两窗就是多两段 FFT。
- **取置信最高窗**：恰好是最容易被「自信的错」骗到的选法。
- **置信加权平均**：一个离谱值就能把结果拖偏。
- **三窗 + 中位数 + 一致比例（选了这个）**：中位数免疫单个离谱值，一致比例决定值不值得信。

## 后果

- 三窗互不一致时**不硬融**（`w=1`），行为与 v1.11.0 完全一致。
- 头窗测歪时，头锚点从中窗按融合 BPM 外推，不再照抄错的相位；尾窗同理。
- 记录里的 `w` 是「融合窗口数」，不是「算过几个窗」—— `w=1` 也可能已经补算过（`tried=3`）。
- 融合只覆盖 BPM / 拍长 / 置信；调性仍只取头窗，能量曲线仍是整首每秒一个值。
